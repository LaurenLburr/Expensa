2. BUDGET ARCHITECTURE DECISIONS LOCKED IN
==================================================

These decisions are important and should be treated as current truth.

2.1 Budget Template Behavior
The template is no longer a live ongoing source once a month is created.

Rule:
- When a new budget month is created, template defaults are copied into BudgetMonthPayee.
- After that, the month owns its own state.
- Changes to Payee defaults must NOT retroactively change existing month budgets.

This means:
- BudgetMonthPayee is the month snapshot.
- Existing month data is edited only in BudgetMonthPayee.
- Template/defaults are seed data only.

2.2 Payee Stores Defaults
Payee now conceptually stores:
- IncludeInBudgetTemplate
- DefaultAccountId
- DefaultAmount

Those values are used only during month creation.

2.3 Paying Account Behavior
The paying bank account should not need to be manually selected every month in normal use.

Rule:
- Payee.DefaultAccountId is copied into BudgetMonthPayee.AccountId at month creation.
- User can override AccountId in the month budget if needed.
- That override is month-only unless an explicit “make default” feature is added later.

2.4 Default Amount Behavior
Payee.DefaultAmount is the default planned amount for a new month.

Rule:
- DefaultAmount is copied into BudgetMonthPayee.PlannedAmount at creation.
- After that, changes are saved only to the month budget row.

3. CURRENT BUDGET SQL DIRECTION
==================================================

The key budget creation query now reads from Payee and creates month-owned rows.

Final creation query concept:
QueryName:
BudgetMonthPayee.CreateFromTemplate

Behavior:
- Insert BudgetMonthPayee rows for a specific BudgetMonthId
- Use Payee rows where IncludeInBudgetTemplate = 1
- Copy:
  - SortIndex
  - DefaultAmount -> PlannedAmount
  - DefaultAccountId -> AccountId
- Avoid duplicates using NOT EXISTS

Current SQL shape:

INSERT INTO [BudgetMonthPayee]
(
    [BudgetMonthPayeeId],
    [BudgetMonthId],
    [PayeeId],
    [SortIndex],
    [PlannedAmount],
    [AccountId]
)
SELECT
    @BudgetMonthId || '-' || p.[PayeeId],
    @BudgetMonthId,
    p.[PayeeId],
    p.[SortIndex],
    COALESCE(p.[DefaultAmount], 0),
    p.[DefaultAccountId]
FROM [Payee] p
WHERE p.[IncludeInBudgetTemplate] = 1
AND NOT EXISTS
(
    SELECT 1
    FROM [BudgetMonthPayee] bmp
    WHERE bmp.[BudgetMonthId] = @BudgetMonthId
      AND bmp.[PayeeId] = p.[PayeeId]
);

Important note:
This query should be stored in SqlQuery using UPSERT logic.

4.2 SqlQuery.SelectCatalog
This query must return IsActive too.

Shape:

    [QueryName],
    [Category],
    [Description],
    [SqlText],
    [IsActive]

    [Category],
    [QueryName];

7.4 PayeeDetailsForm Tag UI Direction
The desired UI pattern for Payee tagging is:

- Textbox for typing tag name
- ListBox below showing partial matches as user types
- If textbox empty, listbox empty
- Link to create/add tag
- If typed tag is not new, link is disabled
- Better recommended behavior:
  - If exact existing tag match and payee does not already have it:
    allow assign
  - If tag is new:
    allow create + assign
  - If blank:
    disable

This work belongs on PayeeDetailsForm, not PayeesLandingForm.

8.3 Tags Node Behavior
Selecting Tags should NOT just show a flat filter list.

Desired Payee tree under Tags:

  Tags

      Untagged Payee A
      Untagged Payee B

      Water

      Internet

Same pattern later for Websites.

Important:
- “None” means no tags assigned
- items are shown under each tag
- an item may appear under multiple tags if it has multiple tags
- this is grouped navigation view, not just filtering
